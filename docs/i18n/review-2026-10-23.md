### 1.4 Missing Keys & Unlocalized Code Paths (Android)

1. **`Labels.category()` (`Labels.kt:208-220`) — 19 of 31 place categories render in raw English & 4 categories collide:**
   - `PLACE_CATEGORIES` in `AddPlaceScreen.kt:53` defines 31 categories, but `Labels.category()` only maps 12 of them. The remaining 19 (`supermarket`, `convenience`, `pharmacy`, `school`, `hotel`, `atm`, `bank`, `car_repair`, `car_wash`, `temple`, `church`, `tourism`, `transit_station`, `university`, `government`, `airport`, `other`, etc.) hit `else -> c.replace('_', ' ').replaceFirstChar { it.uppercase() }` and display raw English in Malay mode.
   - **Category collisions in `Labels.category()`:**
     - `restaurant`, `cafe`, and `fast_food` all return `R.string.cat_food` (`"Makan"`), producing **three identical "Makan" tiles** in the Add Place category grid!
     - `mosque` and `surau` both return `R.string.cat_mosque` (`"Masjid"`), even though `R.string.sc_surau` (`"Surau"`) already exists.
     - `hospital` and `clinic` both return `R.string.cat_hospital` (`"Hospital"`).
2. **`AMENITIES` in `AddPlaceScreen.kt:173` — completely unlocalized:**
   - The 12 amenity chips (`toilets`, `surau`, `parking`, `wifi`, `card_payment`, `ewallet`, `wheelchair`, `air_conditioning`, `ev_charging`, `atm`, `food`, `air_pump`) are rendered via `a.replace('_', ' ').replaceFirstChar { it.uppercase() }` with no `strings.xml` entries.
3. **`OpeningHours.DAYS` in `AddPlaceScreen.kt:205` — uses raw OSM codes instead of `day_mo`..`day_su`:**
   - Renders raw `"Mo"`, `"Tu"`, `"We"`, `"Th"`, `"Fr"`, `"Sa"`, `"Su"` even though `R.string.day_mo`..`R.string.day_su` (`Isn`..`Ahd`) are already defined in `strings.xml`!
4. **Raw backend requirement codes in `ContributionsScreen.kt:1525`:**
   - `stringResource(R.string.next_tier, next.tier, next.missing.joinToString(", "))` outputs raw server tokens like `"placesAccepted:7, accuracy:90"` to the user in Malay and English, whereas iOS formats them via `NextTierText.describe()`.
5. **Missing key in `values-ms/strings.xml`:**
   - `app_name` (`Gimano`) is in `values/strings.xml` but omitted from `values-ms/strings.xml` (mark `translatable="false"` in `values/strings.xml`).
6. **Search / map keys from brief not yet in `strings.xml`:**
   - Add keys for `"Select on map"` → `"Pilih pada peta"`, `"Nearest"` → `"Terdekat"`, and `"Did you mean"` → `"Maksud anda"` when wiring those search UI elements.

### 2.4 Missing Keys & Unlocalized Code Paths (iOS)

1. **`ReviewsAndPhotos.swift:1254` (`MyPlaceEditRow`) — bypasses `Localizable.xcstrings` and `"Published"` is missing:**
   - Code: `Text(status == .pending ? "Unverified" : status == .published ? "Published" : status.rawValue.capitalized)`
   - Because ternary expression returns a `String` rather than a `LocalizedStringKey`, SwiftUI does **not** look it up in `Localizable.xcstrings`. Furthermore, `"Published"` has no entry in `Localizable.xcstrings` (add `"Published"` → `"Diterbitkan"`).
2. **`PlaceCardView.swift:643` — amenities on Place Card are unlocalized in Malay:**
   - Code: `Text(a.replacingOccurrences(of: "_", with: " ").capitalized)`
   - While `AddPlaceFlow.swift:187` properly maps amenity keys to localized strings (`Tandas`, `Surau`, `Tempat letak kereta`, ` Kad`, `E-dompet`, `Mesra kerusi roda`, `Penyaman udara`, `Pengecas EV`, `Pam angin`), `PlaceCardView.swift:643` renders raw English (`Toilets`, `Card Payment`, `Air Conditioning`, etc.). Extract `AddPlaceFlow.amenityLabel(_:)` to a shared helper and use it in `PlaceCardView`.
3. **`DriveView.swift:793` (`DriveAlternativesSheet`) — `Text(String)` bypasses localization:**
   - Code: `Text(r.trafficDescription ?? "")`
   - `r.trafficDescription` is a `String` (`"Typical traffic"`, `"Heavier than usual"`, `"Light traffic"`). Passing a `String` variable to `Text(...)` skips `Localizable.xcstrings` even though those exact keys exist in the catalog! Use `Text(LocalizedStringKey(t))` as `RoutePreviewView.swift:525` does.
4. **`AddPlaceFlow.swift:473` (`OpeningHoursEditor`) — unlocalized day abbreviations:**
   - Code: `Text(d.osm)` renders raw `"Mo"`, `"Tu"`, `"We"`, `"Th"`, `"Fr"`, `"Sa"`, `"Su"` instead of localized `"Isn"`, `"Sel"`, `"Rab"`, `"Kha"`, `"Jum"`, `"Sab"`, `"Ahd"`.
5. **`FavoritesViews.swift:411` (`IconPicker`) — raw enum accessibility labels:**
   - `.accessibilityLabel(Text(i.rawValue))` reads raw enum identifiers (`mertua`, `kampung`, `briefcase`) to VoiceOver instead of localized labels.
6. **Search / map keys from brief not yet in `Localizable.xcstrings`:**
   - Add `"Select on map"` → `"Pilih pada peta"`, `"Nearest"` → `"Terdekat"`, and `"Did you mean"` → `"Maksud anda"`.

## Part 3 — English Copy Clarity & Cross-Platform Consistency Review

1. **Shorten verbose English button labels (both platforms):**
   - `Find the best time to leave` (27 chars) → **`Best time to leave`** (18 chars).
   - `It's here, but the pin is in the wrong spot` (iOS, 43 chars) → **`Wrong pin location`** (18 chars) or **`Pin is in wrong spot`** (20 chars) to match Android's concise **`Wrong pin`**.
   - `Plan this drive (reminder)` (iOS, 26 chars) → **`Plan drive`** (10 chars, matching Android `plan_drive`).
   - `Change app language (English / Bahasa Melayu)` (iOS, 45 chars) → **`App language`** (12 chars).
2. **Unify report category & status labels between Android and iOS:**
   - Road closure is `Road closed` on Android (`report_closure`) vs `Closure` on iOS (`ReportCatalog.swift`). Prefer **`Road closed`** (`Jalan ditutup`) on both.
   - Contribution pending status is `Waiting for verification` on Android (`status_pending`) vs `Unverified` on iOS. Standardize on **`Unverified`** (`Belum disahkan`) for compact badges and **`Waiting for verification`** (`Menunggu pengesahan`) for detail descriptions.
3. **Clarify `planned_notify` placeholder order on Android:**
   - `Leave by %1$s to reach %3$s by %2$s` uses non-sequential positional arguments (`%1$s`, `%3$s`, `%2$s`), which caused the Malay word-order bug (`sampai %2$s di %3$s`). Document the parameter meanings in an XML comment (`<!-- %1$s = leave time, %2$s = arrival time, %3$s = destination -->`) so translators don't swap `%2$s` and `%3$s`.
